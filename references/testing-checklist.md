# قائمة فحص ما قبل التسليم

تحقق من البنود المنطبقة قبل التسليم، وأضف اختبارات خاصة بأي سلوك جديد.

---

## 1. التكامل مع مشغّل المختبر (`player.html`)

- [ ] لا بطاقة تعليمات مكررة أو عائمة؛ نص كل خطوة في القائمة، وتلميح الخطأ تحت الخطوة الحالية.
- [ ] القائمة مميزة للحالية بـ`aria-current="step"` وخلفية مختلفة؛ التمرير التلقائي يبقي الحالية والتالية ظاهرتين قدر الإمكان.
- [ ] الشريط مفتوح افتراضياً وقابل للطي/الإظهار دون تعتيم الساحة؛ تتسع الساحة عند الطي ويعاد قياس الكانفاس.
- [ ] على الهاتف العمودي يظهر الشريط كدرج سفلي، وزر إعادة الفتح في منتصف أسفل الشاشة.
- [ ] الشريط الجانبي: `padding-top: calc(64px + 12px)` (= 76px) على ترويسته.
- [ ] طاولة العمل: أول 70px (`SAFE_TOP`) خالية من الأدوات والنصوص، وتُقرأ القيمة من `--bench-safe-top` (🆕 مصدر واحد).
- [ ] 🆕 لا يمكن سحب أداة إلى ما تحت `SAFE_TOP` (الحصر مطبّق).

## 2. المعمارية والتوزيع

- [ ] المحاكاة عربية (`rtl`) والشريط يميناً، من دون مبدّل لغة أو نصوص واجهة إنجليزية.
- [ ] طاولة العمل تمتد على كل المتبقي بلا أشرطة تقطعها.
- [ ] قائمة الخطوات تتحول لـ [✓] أخضر لحظياً.
- [ ] 🆕 يبقى تذييل `[إعادة] [التقدم] [التالي]` ظاهراً أسفل الشريط حتى مع نصوص طويلة تُمرَّر (التمرير على `.sb-scroll` لا على الشريط كله).
- [ ] 🆕 مؤشر التقدم يعكس الخطوة الحالية، وزر `#next` ينقل للخطوة التالية ويتعطل بعد اكتمالها؛ `#rst` يعيدها إلى البداية.
- [ ] 🆕 نص طويل في بند الخطوة/التلميح لا يخرج من الشريط ولا يخفي أزرار التذييل.

## 3. الجودة الفنية والرسوم

- [ ] لا أيدٍ عائمة كفاعل؛ يد المريض (إن وُجدت) مستندة على وسادة.
- [ ] الأدوات تستقر على الطاولة أو في حوامل، لا في شريط سفلي مستقل.
- [ ] عند استخدام الرفوف: تستقر قواعد الأدوات الفعلية من `Kit` فوق سطح اللوح بلا تقاطع أو تداخل؛ بطاقات الأسماء مثبتة على واجهة الرف وتحمل أسماء مناسبة للمحتوى، لا فئات مفروضة.
- [ ] لا تظهر أسماء الأدوات أو الأواني باستمرار؛ يظهر اسم العنصر الصحيح عند تحويم المؤشر عليه، ويختفي التلميح عند مغادرته أو بدء السحب ولا يعترض التفاعل.
- [ ] مساحة الطاولة مناسبة، وواجهة حافتها وظلها خفيفان بألوان الهوية؛ لا توجد عناصر رفوف زخرفية لا تخدم التجربة.
- [ ] تدرجات وظلال بدل الألوان المسطحة.
- [ ] 🆕 **كل جهاز مرسوم بـ `Kit`** (أو بجهاز جديد وفق الوصفة) دون إعادة رسم جهاز موجود.
- [ ] 🆕 **فُحصت الرسوم بصرياً** (kit-preview أو لقطة) والجهاز يُعرَف من شكله.
- [ ] 🆕 ضوء من أعلى اليسار في كل العناصر، وظل تماس تحت كل جهاز واقف، وكل ألوانه من `Kit.pal`.
- [ ] 🆕 سُئل المستخدم عن مصدر الرسوم؛ وإن استُخدمت صور فهي base64 داخل الملف مع بديل `Kit`، وحجمها ضمن الميزانية (≤150KB للصورة، ≤600KB للمجموع).
- [ ] 🆕 **الموضوع ضمن علوم الطبيعة والحياة** (لا فيزياء ولا كيمياء محضة)، وأجهزة المخبر تخدم تجربة SVT.
- [ ] 🆕 لم تُرسم أي أداة يدوياً خارج `Kit` مع وجود نظيرها فيه (فهرس drawing-standards §3).
- [ ] 🆕 لم تُجلب أي صورة من الإنترنت.
- [ ] 🆕 لا `shadowBlur` ولا `ctx.filter` داخل حلقات متكررة.

## 4. التفاعل والوظيفة

- [ ] لا أزرار Play/Pause؛ أزرار التذييل `#next` و`#rst` ومؤشر التقدم مطابقة للقالب.
- [ ] Pointer Events (فأرة + لمس)، مؤشر واحد نشط، `setPointerCapture` و`touch-action:none`.
- [ ] إفلات في الفراغ = عودة سلسة للجيب.
- [ ] 🆕 **العناصر الدوّارة/المنزلقة** (برج عدسات، حلقة بؤرة): تعمل بالتدوير/الانزلاق لا بالسحب؛ لا قفزة عند عبور ±π؛ تستقر عند نقطة توقف؛ الخطوة لا تُنجَز إلا بعد الاستقرار.
- [ ] 🆕 **ظهور العناصر حسب المشهد:** عند كل `setScene` لا يبقى أي عنصر مرسوماً أو قابلاً للّمس خلف لوحة أخرى (جرّب كل انتقال).
- [ ] 🆕 `#rst` يعيد كل شيء: الخطوات، المشهد، مواضع الأدوات، قيم الدوّارات، البؤرة، الطبقات المخزّنة.
- [ ] 🆕 خطأ المتعلم يُنتج تلميحاً هادئاً ولا يغيّر الحالة.
- [ ] 🆕 لمسة ثانية أثناء سحب لا تُحدث سلوكاً غريباً.
- [ ] عند وجود نموذج زمني، النتائج تتبع النموذج ووحداته ولا تعتمد على سرعة الإطارات؛ وإعادة الضبط تعيد النموذج والحركة.
- [ ] المؤثرات المرئية محدودة وتتوقف عند السكون، وتُخفض أو تتوقف مع `prefers-reduced-motion`.

## 5. المحاكاة البصرية (للأجهزة البصرية فقط) 🆕

- [ ] قناع **مجال رؤية** دائري؛ قطر المجال = رقم المجال ÷ تكبير الشيئية (يصغر بزيادة التكبير).
- [ ] **البؤرة** تُمزج تدريجياً (حاد ↔ ضبابي) وتضيق مسافة التسامح مع التكبير الأعلى.
- [ ] التكبير الكلي المعروض = الشيئية × العينية.
- [ ] شريط مقياس بالميكرومتر صحيح.

## 6. الأداء 🆕

- [ ] الحالة الساكنة لا تستهلك معالجاً (لا `rAF` دائمة؛ dirty rendering).
- [ ] العناصر المتكررة (مئات الخلايا) مرسومة في طبقة/سبرايت مخزّن، لا كل إطار.
- [ ] زمن `draw()` < 6ms على جهاز متوسط (قِس بـ `performance.now()`).
- [ ] DPR مسقوف عند 2.
- [ ] `visibilitychange` و`prefers-reduced-motion` مُعالَجان.

## 7. الاستجابة للأحجام 🆕

اختبر كل مقاس وتحقق أن الأجهزة داخل الطاولة وأن عناصر اللمس ≥ 22px:

| المقاس | الحالة |
|---|---|
| 1920×1080 | سطح مكتب |
| 1366×768 | حاسوب محمول (ارتفاع قصير) |
| 1280×560 | ارتفاع صغير جداً (نافذة مقلّصة) |
| 768×1024 | لوح عمودي |
| 844×390 | هاتف أفقي |
| 390×844 | هاتف عمودي (الشريط يصير درجاً سفلياً) |

- [ ] تغيير حجم النافذة أثناء التشغيل يعيد الحساب ولا يكسر الحالة.
- [ ] تظل الرفوف المنفصلة وتسميات ألواحها والأدوات عليها واضحة وغير متداخلة مع منطقة الأمان أو حافة الطاولة عند تغيير الحجم.
- [ ] لا شريط تمرير أفقي في الصفحة.

## 8. التقنية واللغات

- [ ] ملف واحد مستقل، بلا مكتبات أو خطوط أو روابط خارجية.
- [ ] DPR مطبّق (لا تشوش خطوط).
- [ ] `lang="ar"` و`dir="rtl"` ثابتان؛ كل النصوص الظاهرة للمتعلم (بما فيها داخل الكانفاس والتلميحات) بالعربية.
- [ ] 🆕 **التوافق:** polyfill لـ `ctx.roundRect` موجود قبل أول رسم؛ لا اعتماد على `ctx.filter` أو `OffscreenCanvas`.
- [ ] سجل وحدة التحكم نظيف (لا أخطاء ولا تحذيرات).
